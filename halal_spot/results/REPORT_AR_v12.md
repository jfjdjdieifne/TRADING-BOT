## 1. ملاحظة مهمة عن الأزواج (قبل النتائج)

> ADAUSDT / AVAXUSDT / LINKUSDT / SUIUSDT).** المشروع لا يحتوي على أي بيانات شموع لها —
> يوجد فقط `BTCUSD_5m`. لذلك اقتصر الاختبار على BTCUSDT حصراً، وهذا يغيّر سلوك
> الاستراتيجية جزئياً:

> - `_regime` يُحسب من زوج واحد بدل متوسط كل الأزواج (يصبح `bull/bear` قراءة BTC وحدها).

## 2. نزاهة الاختبار — اختبارات الـ Zero-Lookahead (ماتغش بالفحص)

المحرك المنسوخ إلى المجلد: `engine/causal_primitives.py` (من `smc_v4_multisleeve_package`)،
ومراجع اختباراته في `reference/test_v4_zero_lookahead.py`.

**الاختبارات المنفذة — 9/9 ناجحة** (`python3 -m pytest tests/`):

| الاختبار | الفكرة | النتيجة |
|---|---|---|
| resample prefix invariant | قص الشموع عند `2026-03-31 14:30` لا يغيّر أي شمعة 15m/1h/4h مكتملة قبل القص | ✅ |
| closed trades identical before cut | كل صفقة أُغلقت قبل القص مطابقة حرفياً (bit-for-bit) للتشغيل الكامل | ✅ |
| open trade setup identical | الصفقة المفتوحة وقت القص: نفس إعداد الإشارة بالكامل | ✅ |
| equity curve identical before cut | منحنى Equity قبل القص مطابق تماماً | ✅ |
| no trades after end | التشغيل المقصوص لا يخترع صفقات بعد نهايته | ✅ |
| first half == standalone | النصف الأول من التشغيل المستمر يطابق التشغيل المستقل حرفياً (حتمية مزدوجة) | ✅ |
| trade timing is causal | إشارة ≤ دخول < خروج، والتنفيذ دائماً بعد إغلاق شمعة الإشارة | ✅ |
| accounting ties to equity | مجموع أرباح الصفقات يفسّر تغير Equity (الفرق = غبار BTC المعاد تقييمه) | ✅ |
| no negative cash or qty | لا رصيد سالب ولا صفقة دون تمويل | ✅ |

**كيف يمنع اللوكهيد:** الإشارات تُبنى فقط على شموع منتهية (end-time labelled)، وأوامر
الشراء السوق (ImmediateFillModel) تُملأ بسعر إغلاق شمعة الإشارة نفسها (لا بيانات قادمة)،
وقوائم الوقف الراكنة تُفحص على **كل شمعة 5m مكتملة** قبل معالجة شمعة الجدد (stop-first:
لمسة الوقف تُملأ `min(open, SL)` لا اللمسة فقط)، والخروجات بـ `liquidate` تُملأ بسعر إغلاق
الشمعة التي وقع فيها القرار (5m داخل `_m5`/`_exit`، أو إغلاق 1h/4h داخل `_trail`) —
لا يُستخدم أي سعر مستقبلي في أي قرار.

|---|---|

| الإحماء | 35 يوم قبل بداية النافذة (`set_warm_up` مطابق — من 2025-06-26) |
| الرسوم | 0.1% لكل تنفيذ (Binance futures) بالـ USDT؛ ثابت `FEE=0.0020` يبقى حرفياً داخل معادلات `min_r`/إحصاءات المحرك |

| الوقف | `stop_market_order` راكد: يُفحص على **كل شمعة 5m**: ل long `low ≤ SL` → ملء `min(open, SL)`؛ لshort `high ≥ SL` → ملء `max(open, SL)`؛ الوقف يسبق معالجة الشمعة الجديدة |
| الخروجات | `liquidate` بسعر القرار: إدارة 5m داخل `_m5`/`_exit` (لمس هدف، synced stop)، و`_trail` عند إغلاق 1h/4h |
| تتبّع الوقف | رفع فقط (لا خفض): BE بعد `min_r + 0.02R`، ثم MFE على 1h/4h مع `pad = 0.5×ATR1 / 1.5×ATR4` |
| المحركات الأربعة | ARM1_4H (g4) / ARM2_1H (g1) / ARM3_IGN (gi) / ARM4_SWP (gs) + بوابة `_gate`/`_score` |
| الحجم | `rbudget = 0.10`؛ `rk = eb × _rpct(ap) × (0.85 + 0.35×مزيج cf/score)`؛ lev ∈ {1.8, 2.4, 3.2} × `eb` كحد أدنى إسمي؛ `notional = min(rk/(rd/px+0.0012), eb×lev, margin_remaining×5.8)` |
| الوضع الأسبوعي | `on_data` يقلب TURBO/DAILY أسبوعياً (≥+4% أسبوع = TURBO) — يعمل آخر أمر في كل شريحة كما في LEAN |
| إغلاق نهاية النافذة | أي مركز مفتوح يُغلق بسعر آخر شمعة بوسم `EOD` (كما في `on_end_of_algorithm` الحافّة) |
| دفعة الإدخال | الإشارة والتنفيذ على نفس إغلاق الشمعة (سعر الإشارة هو سعر التنفيذ — لا معلومة مستقبلية) |

**سلوكيات من الكود الأصلي V12 أُبقيت كما هي (ولم تُصلَح):**
1. `_target` يُعيد `None` بمفهوم «جدار ضعيف» (وليس `0.0`)، والفحص `if tp is None` كما هو — مسار فحص `if tp == 0.0` للمتبقي ميّت، محفوظ.
2. `mkN` (same-wave) يُحدَّث عند الطلب لا عند التأكيد — كما في الأصل.
3. `entk` المعلّقة ومسارها في `_on_5m`/`on_order_event` محفوظان كما هما — مسار ميّت تحت ImmediateFillModel.
4. `_rst` يلغي `sltk` فقط و`_fin` يستدعي `_rst` بعد التسجيل — كما في الكود.
5. `_trail` الإشارية السفلية تشترط `is4 == False` و/ph==1 فقط (مسار ميّت على 4h كما في الأصل).
6. `_raise` يرفض الرفع عند `sd×(c − nsl) ≤ 0` (إغلاق اليوم أسفل/أعلى الوقف الجديد للشورت/اللانج) — كما هو.
7. ملاحظة قياس: قمع `_regime` في الكود الأصلي يعدّ `b` و`r` ثم يقرّر؛ مع زوج واحد يصبح `b/r ∈ {0,1}`.
8. `_margin_remaining` يُقرَّر على `equity×10` (نموذج LEAN InitialMargin) — تقريب موثّق لا يمس معادلات الدخول.
