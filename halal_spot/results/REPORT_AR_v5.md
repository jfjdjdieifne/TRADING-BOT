## 2. نزاهة الاختبار — اختبارات الـ Zero-Lookahead (ماتغش بالفحص)

المحرك المنسوخ إلى المجلد: `engine/causal_primitives.py` (من `smc_v4_multisleeve_package`)،
ومراجع اختباراته في `reference/test_v4_zero_lookahead.py`.

**الاختبارات المنفذة — 9/9 ناجحة** (`python3 -m pytest tests/`):

| الاختبار | الفكرة | النتيجة |
|---|---|---|
| resample prefix invariant | قص الشموع عند `2026-03-31 14:30` لا يغيّر أي شمعة 15m/1h/4h مكتملة قبل القص | ✅ |
| closed trades identical before cut | كل صفقة أُغلقت قبل القص مطابقة حرفياً (bit-for-bit) للتشغيل الكامل | ✅ |
| open trade setup identical | الصفقة المفتوحة وقت القص: نفس إعداد الإشارة بالكامل | ✅ |
| equity curve identical before cut | منحنى Equity قبل القص مطابق تماماً | ✅ |
| no trades after end | التشغيل المقصوص لا يخترع صفقات بعد نهايته | ✅ |
| first half == standalone | النصف الأول من التشغيل المستمر يطابق التشغيل المستقل حرفياً (حتمية مزدوجة) | ✅ |
| trade timing is causal | إشارة ≤ دخول < خروج، والتنفيذ دائماً بعد إغلاق شمعة الإشارة | ✅ |
| accounting ties to equity | مجموع أرباح الصفقات يفسّر تغير Equity (الفرق = غبار BTC المعاد تقييمه) | ✅ |
| no negative cash or qty | لا رصيد سالب ولا صفقة دون تمويل | ✅ |

**كيف يمنع اللوكهيد:** الإشارات تُبنى فقط على شموع منتهية (end-time labelled)، وأوامر
الشراء السوق تُملأ بسعر إغلاق شمعة الإشارة نفسها (لا بيانات قادمة)، وTP1 كطلب حدّي يُملأ
أوّل شمعة 5m **بعد** لحظة الوضع فقط، والوقفات تُفحص على **كل شمعة 5m مكتملة** وعند
إغلاق 15m — لا يُستخدم أي سعر مستقبلي في أي قرار.

## 3. إعداد المحاكاة (مطابق للكود الأصلي مع فروق موثّقة)

| البند | القيمة |
|---|---|
| رأس المال | 100 USDT، `set_cash` مطابق للكود |
| بيانات الشموع | `data/BTCUSD_5m/` (نسخة داخل المجلد — 2019..2026) |
| فترات التحليل | 15m / 1h / 4h بإعادة تجميع سببية (causal) |
| الإحماء | 14 يوم قبل بداية النافذة (من 2025-06-17) |
| رسوم التداول | 0.1% لكل تنفيذ (Binance spot) محسوبة من USDT |
| الخصائص | tick = 0.01، lot = 0.00001، الحد الأدنى 5.5 USDT |
| ملء أوامر الدخول | أمر سوق يُملأ **فوراً** بسعر إغلاق شمعة الإشارة (ImmediateFillModel — نفس سلوك الكود الأصلي) |
| TP1 | حد بيع راكد يُطابَق على **كل شمعة 5m**: `high ≥ TP1` → بيع 50% (أو 100% إن كان الباقي دون الحد الأدنى) عند `max(open, TP1)`، ورفع وقف النصف المتبقي فوراً إلى `max(sl, ep+1.75R)` كما في `on_order_event` |
| الوقف/التتبع | يُفحص على **كل شمعة 5m** (`on_data`) ويُنفذ بـ `min(open, SL)` + عند إغلاق 15m بعد Ratchet — محاكاة Stop-Market دقيقة بلا لوكهيد |
| هندسة الدخول | `Net_RRR ≥ 3.0` بعد الرسوم: `P_max = (M + 3F) / (4×(1+f))` بـ `f = 0.0020` — قرار فوري / انتظار / إلغاء تلقائي |
| إغلاق نهاية النافذة | أي مركز مفتوح يُغلق بسعر آخر شمعة بوسم `EOD` |
| دفعة الإدخال | الإشارة والتنفيذ على نفس إغلاق الشمعة (سعر الإشارة هو سعر التنفيذ — لا معلومة مستقبلية) |

**سلوكيات من الكود الأصلي V5 أُبقيت كما هي (ولم تُصلَح):**
1. `ticket.cancel()` داخل `_rst` — التذاكر في الـ port قواميس، الاستثناء يبتلعها تماماً كما في QC (سلوك متطابق).
2. مسار "بيع أقل من 5.1$" في `_sell_spot` يتجاوز البيع لكنه يصفّر الحالة — محفوظ كما هو.
3. `max_pos = 3` محفوظ كما هو (يتحول عملياً لمركز واحد لوجود زوج واحد).
4. كتلة `entk` المعلّقة في `_on_15m` وفرع `entk` في `on_order_event` محفوظان كما هما — مسار ميّت تحت ImmediateFillModel، لكن الكود مثبّت 1-ل-1.
5. `_held_qty` في V5 **بدون** قصّة 0.999 (اختلاف عن V1/V2 — مطابق حرفي لكود V5): الغبار من تقريب اللوت فقط.
