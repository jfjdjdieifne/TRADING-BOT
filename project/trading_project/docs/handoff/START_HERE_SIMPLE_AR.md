## 1. المشروع بجملة واحدة

> المشروع **لا يتنبأ بالسوق**. المشروع يأخذ كلام المنشورين عن مفاهيم `ICT`، ويحوّله إلى
> **تعريفات دقيقة قابلة للاختبار**، وإذا كان الكلام ناقصًا **لا يخترع رقمًا**، بل يطبع
> «هنا يوجد سؤال بلا جواب».

تشبيه: نحن لا نبني "عرّافًا"، نحن نبني **قاموسًا صارمًا + محاسبًا** لكل جملة نقرأها.

## 4. الخريطة الثالثة: كيف يفكّر الكود (هذه هي "العقلية")

أي دالة تأخذ شمعة وتعطي حكمًا، تمرّ بنفس المسار:

```
           شمعة عند الفهرس t
                    │
                    ▼
      ┌─────────────────────────────┐
      │ 1) هل المدخل سليم؟          │  high<low؟ مفتاح closed غائب؟ قيمة نصية؟
      │    لا ← استثناء ValueError  │  ← لا "تصحيح صامت" ولا قيمة افتراضية
      └──────────────┬──────────────┘
                     ▼
      ┌─────────────────────────────┐
      │ 2) هل الشمعة مغلقة؟         │  لا ← PENDING (لا حكم قبل الإغلاق)
      └──────────────┬──────────────┘
                     ▼
      ┌─────────────────────────────┐
      │ 3) هل النص يحكم؟            │
      │   نعم → BUILT + YES/NO      │
      │   مساواة بالعتبة → UNDECIDED│
      │   لا نص → UNDEFINED + فجوة  │
      └──────────────┬──────────────┘
                     ▼
      ┌─────────────────────────────┐
      │ 4) السجل المطبوع يحمل:       │
      │   tier=TIER2, status,        │
      │   variant_id, claim_ids,     │
      │   source_numbers, numbers,   │
      │   last_read (لا نظر للأمام), │
      │   gaps[], dimension_gaps[]   │
      └─────────────────────────────┘
```

وأي سؤال يواجهنا، الجواب يُقرَّر بهذه الشجرة **قبل** كتابة أي كود:

```
        هل المصدر أعطى رقمًا؟
             │
     ┌───────┴────────┐
    نعم               لا
     │                 │
     ▼                 ▼
SOURCE_NUMBER    هل نحن مضطرون لرقم؟
(يُطبع مع         │
 معرّف           ┌─┴──────────────┐
 ادعائه)       نعم                لا
                │                  │
                ▼                  ▼
        ENGINEERING_CHOICE     KNOWLEDGE_GAP
        (يُعلن قبل الشيفرة،    (يُطبع السؤال،
         سببه: أقل مدخلات،      والنتيجة UNDEFINED،
         ليس "أفضل")            ولا يُخترع جواب)
```

مثال حقيقي يوضّح لماذا هذا مهم:

> عائلة إزاحة تقول «جسم الشمعة ≥ 1.5 × ATR(14)». المصدر أعطى `1.5` و`14` — **ولم يقل كيف
> يُحسب ATR**. النتيجة عندنا: النسخة موجودة، ترجع `UNDEFINED`، وتطبع
> `KNOWLEDGE_GAP: ATR formula` + أربعة أسئلة للمالك. **لم نكتب الصيغة الشائعة.**

## 6. شو يعني "شغّال"؟ (اقرأ هذا قبل أي حكم)

| "شغّال" عندنا تعني | "شغّال" **لا** تعني |
|---|---|
| كل تعريف يعطي نفس الجواب في كل مرة | أنه يربح |
| كل رقم مأخوذ من مصدر أو قرار معلن | أنه يتنبأ بالسوق |
| كل حالة غامضة تُطبع كسؤال لا كتخمين | أن المنهج "أفضل" من غيره |
| الاختبارات تحرس كل هذا آليًا | أننا جاهزون للتداول |

**قرار التصميم:** لا نتائج على بيانات حقيقية في هذه المراحل. لماذا؟ لأن أي رقم أداء قبل
تجميد التعريف = تضليل و`look-ahead`. المكسب الحقيقي في هذه المرحلة: **معرفة دقيقة قابلة
للاختبار**، لا نسبة ربح.

## 10. أخطاء شائعة تجعلنا نبدأ من الصفر (تجنّبها)

1. تعديل ملف توقعات ليمرّ الاختبار ← يهدم فكرة "الاختبار قبل الكود" بالكامل.
2. إدخال رقم جديد "لأنه منطقي" ← يفتح باب كل الأرقام الاعتباطية.
3. تشغيل المنهج على بيانات حقيقية الآن ← يعطي نتائج لا معنى لها ويعطّي التصميم.
4. نسخ قاعدة من الكود القديم ← يُدخل أرقامًا من مصدر مجهول (مثل مخاطرة `1%`).
5. إعلان "خلصنا" لأن الاختبارات نجحت ← النجاح ≠ الإغلاق.
