# REUSE DECISIONS V1 — one row per pipeline step

Read before deciding: `engine_v1/b1_candles/*`, `engine_v1/c1_catalog/*`, `src/trading_system/{ict_engine,
zones,structure,liquidity,multitimeframe,environment,recommendation}`, `research/trajectory/trajectory_stage4b2.py`,
`huddleston_study/run_forex_intraday_v1.py`, `engine_v1/OLD_PIPELINE_DO_NOT_REUSE.md`.

The registry flags (`CAPABILITY_REGISTRY_V1`) were **not** used as a reason anywhere below; every "why" comes
from reading the module named in the row.

Rule applied: an existing causal, tested implementation is reused when its **input shape** is a candle
sequence that can be sliced causally and its **return** is a per-bar record. Batch engines that answer for
every bar of a prefix at once are used as **oracles in the fixtures**, not in the per-bar loop, because the
run needs one decision per bar inside a bounded memory envelope.

## The one module that must not be used

`recommendation/causal_ict_lifecycle.py` (1,205 lines) is named in `OLD_PIPELINE_DO_NOT_REUSE.md` for **eleven**
separate items — global risk 1 %, an all-inclusive R gate, unsourced cost/threshold/warm-up/expected-value,
absolute position bans, algebraic partial fractions, automatic re-entry, forced break-even and swing
ratchets, mandatory market exit, fake mitigation flags, synthetic target projections, seeds and pinning. It is
therefore **not imported and not copied**; the only place its name appears is this row and the log file it is
already in.

## What the reuse actually buys

- 9 of 19 steps are an existing, tested, per-bar or bucket-causal function called with a sliced candle list.
- 8 steps are new code whose *definitions* are copied (by id and vocabulary) from the reused modules and whose
  batch versions are used as oracles in the fixtures.
- 2 steps (order-block prerequisite chain, T2) are a caller decision on top of a reused ranking, declared.

## What this does NOT establish

- It does not establish that any reused function is *correct about the market*; it establishes that the rule
  it implements is printed, sourced and causal in the sense its own docstring claims.
- "Tested" here means the module has a fixture file in `engine_v1` (802 / 402 / 139 checks); it does not mean
  the module was tested on real EURUSD data.
- Rejecting a module for cost or dependency weight is an engineering judgement, not a finding that the module
  is wrong.
- The oracle comparisons in the fixtures prove agreement on the fixture bars only, not on 2021-06.
